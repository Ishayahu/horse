# HORSE — инструкции исполнителям
**Единая точка запуска и очередь исследований: [RESEARCH-RUNNER.md](RESEARCH-RUNNER.md).** При запросе «продолжай исследования» сначала прочитать этот файл; он определяет текущую тему и следующую. Существующие `state/` и `docs/` продолжают хранить точное состояние и методологию текущей темы. Не переходить к следующей до документированного завершения текущей.
Прочитайте docs/methodology.md и docs/data-contract.md. Они обязательны для координатора и воркеров.
GitHub Ishayahu/horse — единственный источник истины. Сначала читать state/project.json, state/handoff.md, state/tasks.jsonl, data/coverage.json и фактические результаты. Проверять текущую ветку и историю. Повторный промпт = восстановление и продолжение; изменённый = только дельта. Сохранять пользовательские материалы.
Координатор запускает до 6 реальных независимых воркеров, когда полезно и поддерживается. Не имитировать параллелизм. Передавать только правила, конкретное задание и релевантные данные. Координатор единолично объединяет и пишет общие индексы. Воркеры возвращают отдельные результаты.
Не начинать массовое исследование до получения основного задания. Основное задание получено: docs/research-assignment.md; актуальный статус только в state/project.json.
После каждой партии: проверить, дедуплицировать, сохранить атомарно, перечитать удалённые данные, обновить checkpoint, выбрать следующую готовую партию без вопроса о продолжении.
Не обещать автоматическое возобновление/фон без проверенного механизма. При недоступности записи явно сообщить; локальные результаты не считать сохранёнными.

## Обязательная тематическая структура отчётов

Каждая независимая исследовательская тема публикует конечные читательские результаты только в `reports/<slug>/`, не смешивая отчёты разных тем. `reports/README.md` — единый навигационный указатель. `HORSE-RESEARCH-001` и `HORSE-SUPPLEMENT-001` → `reports/horse/`; `YIRAT-RESEARCH-001` → `reports/yirat-shamayim/`. Рабочие файлы остаются в собственных каталогах `research/`. При переносе править задачи, генераторы и ссылки; после записи проверять фактические пути. См. `RESEARCH-RUNNER.md`.

## Кодовое имя каждого исследования

Перед запуском читать в `RESEARCH-RUNNER.md` поле `codename` текущей темы. Оно равно имени обеих папок: `research/<codename>/` для **всех** промежуточных материалов/проверок/состояния и `reports/<codename>/` для **всех** итоговых материалов. В каждое новое задание и подзадачу вписывать именно это поле; `id` — не `codename`. Для `HORSE-RESEARCH-001` и `HORSE-SUPPLEMENT-001`: `horse`; для `YIRAT-RESEARCH-001`: `yirat-shamayim`. Старые пути HORSE — задокументированное временное исключение до проверенного переноса (см. раздел 21 методологии), не образец для дальнейшей записи.
