# HORSE — инструкции исполнителям
**Единая точка запуска и очередь исследований: [RESEARCH-RUNNER.md](RESEARCH-RUNNER.md).** При запросе «продолжай исследования» сначала прочитать этот файл; он определяет текущую тему и следующую. Состояние работы принадлежит конкретному `research/<codename>/`, а общая методология — `docs/methodology.md`. Не переходить к следующей до документированного завершения текущей.
Прочитайте docs/methodology.md и docs/data-contract.md. Они обязательны для координатора и воркеров.
GitHub Ishayahu/horse — единственный источник истины. Сначала читать очередь `RESEARCH-RUNNER.md` и фактический checkpoint активной темы: `research/horse/supplement/state.md` для текущего HORSE-SUPPLEMENT, `research/yirat-shamayim/state.md` для YIRAT, `research/reform-deliberation/` для POLICY-REFORM-001, когда он станет CURRENT. Исходное историческое состояние HORSE находится в `research/horse/state/`, а проверенные реестры — `research/horse/data/`.
Координатор запускает до 6 реальных независимых воркеров, когда полезно и поддерживается. Не имитировать параллелизм. Передавать только правила, конкретное задание и релевантные данные. Координатор единолично объединяет и пишет общие индексы. Воркеры возвращают отдельные результаты.
Не начинать новую тему без задания из очереди. Первоначальное исследование HORSE завершено, дополнение — отдельная активная работа в `research/horse/supplement/`; приоритеты и статусы — только в `RESEARCH-RUNNER.md`.
После каждой партии: проверить, дедуплицировать, сохранить атомарно, перечитать удалённые данные, обновить checkpoint, выбрать следующую готовую партию без вопроса о продолжении.
Не обещать автоматическое возобновление/фон без проверенного механизма. При недоступности записи явно сообщить; локальные результаты не считать сохранёнными.

## Обязательная тематическая структура отчётов

Каждая независимая исследовательская тема публикует конечные читательские результаты только в `reports/<slug>/`, не смешивая отчёты разных тем. `reports/README.md` — единый навигационный указатель. `HORSE-RESEARCH-001` и `HORSE-SUPPLEMENT-001` → `reports/horse/`; `YIRAT-RESEARCH-001` → `reports/yirat-shamayim/`; `POLICY-REFORM-001` → `reports/reform-deliberation/`. Рабочие файлы остаются в собственных каталогах `research/`. При переносе править задачи, генераторы и ссылки; после записи проверять фактические пути. См. `RESEARCH-RUNNER.md`.

## Кодовое имя каждого исследования

Перед запуском читать в `RESEARCH-RUNNER.md` поле `codename` текущей темы. Оно равно имени обеих папок: `research/<codename>/` для **всех** промежуточных материалов/проверок/состояния и `reports/<codename>/` для **всех** итоговых материалов. В каждое новое задание и подзадачу вписывать именно это поле; `id` — не `codename`. Для `HORSE-RESEARCH-001` и `HORSE-SUPPLEMENT-001`: `horse`; для `YIRAT-RESEARCH-001`: `yirat-shamayim`; для `POLICY-REFORM-001`: `reform-deliberation`. Исторические материалы HORSE перенесены внутрь `research/horse/`; возвращать файлы на прежние одноуровневые пути запрещено. Обе папки одной темы должны иметь одинаковое кодовое имя.
